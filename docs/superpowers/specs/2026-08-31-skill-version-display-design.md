# Skill 版本显示设计

## 背景

插件当前通过 `.codex-plugin/plugin.json` 声明版本（本次更新为 `1.0.4`）。JSON 底稿已有“规范版本”字段，但该字段表示数据规范，不表示实际执行调查的 skill 版本。用户希望每次使用时能确认当前加载版本，并能在最终报告中追溯版本。

## 目标

- 让每个新任务的首次调查响应明确显示当前 skill 版本。
- 让最终 JSON 和 DOCX 保存实际执行本次任务的 skill 版本。
- 保持插件版本只有一个权威来源，避免手工维护多个版本号。
- 不改变现有用户确认流程、文件命名规则或“规范版本”语义。

## 设计

### 版本来源

`.codex-plugin/plugin.json` 的 `version` 是唯一权威版本源。skill 文档声明运行时读取该版本；生成 JSON 时将同一版本写入顶层 `Skill版本` 字段。`规范版本` 继续表示 JSON 数据规范版本，二者不可互换。

### 对话展示

每个新任务的首次响应，在完整中文调查报告之前输出一行 `Skill 版本：<version>`。后续因用户提出修改而重新展示报告时，不要求重复该行。版本提示是元数据，不计入调查结论，也不影响确认区块。

### JSON 契约

顶层新增必填字段 `Skill版本`，类型为非空字符串。JSON Schema 的顶层 `required` 和 `properties` 同步更新。已有底稿若缺少该字段，应在重新生成或迁移时补齐；不放宽校验以接受缺失版本。

### DOCX 展示

渲染器从 JSON 顶层读取 `Skill版本`，在“报告说明”中与 `规范版本` 一并展示。页脚继续只显示页码，以保持页面简洁。DOCX 不接受独立版本参数，确保 JSON 与 DOCX 不会产生版本漂移。

### 错误处理与兼容性

- 缺少 `Skill版本` 的 JSON 由 Schema 校验拒绝，不生成正式 DOCX。
- 缺少或无法读取插件版本时，skill 不得猜测版本；应明确标记版本不可用并停止正式文件生成，避免产生不可追溯报告。
- 版本字符串按插件 manifest 的 SemVer 原样保存，不在渲染器中重新解析或改写。

## 验证

1. 插件 manifest 校验和 skill 快速校验通过。
2. 带 `Skill版本` 的最小合法 JSON 通过 Schema 校验；缺少该字段的 JSON 被拒绝。
3. DOCX 渲染结果在“报告说明”中包含 `Skill版本` 和 `规范版本`，页脚页码仍正常。
4. skill 文档明确首次响应的展示规则和字段语义。

## 非目标

- 不在每个 DOCX 页脚重复版本号。
- 不移除、重命名或改变“规范版本”。
- 不引入第二个独立的版本配置文件。
